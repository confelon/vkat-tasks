## Подход к построению кода

- Проектируй код в парадигме объектно-ориентированного программирования.
- Выделяй классы с чёткой ответственностью; используй наследование и композицию там, где это упрощает модель.
- Группируй связанные данные и поведение внутри классов, а не в разрозненных функциях.
- Предпочитай интерфейсы и абстракции там, где ожидается расширение.

## Современные решения

- Используй актуальные версии библиотек и идиомы языка (type hints, dataclasses, pydantic, async/await — где уместно).
- Выбирай проверенные и современные инструменты вместо устаревших аналогов.
- Следуй существующим конвенциям проекта; при отсутствии — применяй best practices экосистемы Python.

## Без тестов

- Не создавай unit-, integration- и e2e-тесты.
- Не добавляй файлы test_*.py, *_test.py, pytest-фикстуры и конфигурацию тестов.
- Не предлагай написать тесты, если пользователь явно не попросил.

## Без try-except и лишних проверок

- Не оборачивай код в try-except, если пользователь не попросил обработку ошибок.
- Не добавляй defensive checks: if x is None, if not data, hasattr, лишние assert.
- Не добавляй fallback-ветки «на всякий случай».
- Пусть ошибки всплывают естественно — код должен быть линейным и прямолинейным.

## Простая и понятная логика

- Один метод — одна задача; избегай глубокой вложенности.
- Предпочитай явный код неявному; имена классов и методов должны отражать намерение.
- Не создавай абстракции ради абстракций — только когда они реально упрощают код.
- Минимальный diff: не меняй код, который не относится к задаче.


## Деплой


- Всегда запускай сервисы в docker-compose, без локальных запусков
- Есть 2 docker compose файла: 
dev: без приписок, для локальной разработки с примонтированным кодом
prod: с припиской prod для продовой разработки, весь код внутри контейнера
