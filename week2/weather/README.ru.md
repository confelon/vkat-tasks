# Прогноз погоды (учебный проект)

Студенческий ML-проект: прогноз погоды на месяц вперёд для 52 столиц Европы и бывшего СССР.
Основной фокус — интеграция (сбор данных, пайплайн, веб-сервис), а не продвинутый ML.

Данные о погоде — [Open-Meteo](https://open-meteo.com/) (CC-BY, бесплатно, без API-ключа).

## Выводы

- Прогноз на 30 дней — это в основном уточнённая сезонная норма: средний MAE температуры по
  парку моделей — **2,58 °C**, но преимущество над простой климатологией (многолетним сезонным средним)
  невелико — примерно в 40% городов, в основном с мягким климатом (Афины, Рим, Лиссабон…),
  климатология сама по себе не хуже модели.
- **Больше истории — хуже, а не лучше.** Каждое лишнее десятилетие обучающих данных добавляет
  ~0,1 °C систематической холодной ошибки (просачивается старый, более холодный климат) —
  см. бенчмарк глубины истории ниже.
- Предсказуемость определяется климатом, а не моделью: Валлетта (средиземноморский остров) —
  1,40 °C MAE, Астана (резко континентальная степь) — 4,17 °C. Трёхкратный разброс, который не
  закрыть выбором модели.

## Пайплайн

Исторические данные + обучение (офлайн):

```
Open-Meteo → collector.py → data/raw/<City>-YYYY.csv → train.py → <City>-<model>.pkl
```

Прогноз (рантайм, по запросу из браузера):

```
Browser → FastAPI → Open-Meteo (недавняя погода) → ML-модель → прогноз → Browser
```

Данные о погоде кэшируются локально (`app/data/raw/`): обучение воспроизводимо, данные можно
посмотреть глазами, для переобучения не нужно скачивать всё заново.

## Стек

- Бэкенд: FastAPI (только ручки), статику раздаёт сам Python (без nginx).
- Фронтенд: простой HTML + jQuery + plotly.js, без сборки. Все JS-библиотеки лежат локально в
  `app/static/vendor/` — никаких CDN в рантайме.
- Всё запускается через docker-compose: `docker-compose.yml` (dev, каталог `app/` примонтирован,
  uvicorn `--reload`) и `docker-compose.prod.yml` (prod, код запечён в образ).

```bash
# dev
docker compose up --build -d

# prod
docker compose -f docker-compose.prod.yml up --build -d
```

Приложение: http://localhost:8000 · проверка моделей: `/model.html` · бенчмарки парка моделей:
`/fleet.html` · этот документ в браузере: `/readme.html`

## Деплой на реальный сервер

Prod-образ самодостаточен: код, все локально обученные модели (`app/data/*.pkl`) и отчёты
бенчмарков запекаются в образ при сборке. Сырые обучающие CSV в образ не попадают
(`.dockerignore`) — обучение живёт на dev-машине, сервер только раздаёт. Собираем локально,
переносим одним файлом, запускаем на любом Linux с Docker:

```bash
# на dev-машине: собрать prod-образ и упаковать его в один файл
docker compose -f docker-compose.prod.yml build
docker save -o weather.tar weather-weather

# скопировать на сервер и запустить (чистый HTTP на порту 80 — см. модель безопасности)
scp weather.tar user@server:/tmp/
ssh user@server "docker load -i /tmp/weather.tar && \
  docker run -d --name weather --restart unless-stopped -p 80:8000 weather-weather"
```

Обновление: пересобрать, скопировать заново, на сервере — `docker rm -f weather`,
`docker load`, `docker run`. (Одиночный `docker run` заменяет docker-compose на сервере —
контейнер один, компоновать нечего.)

## 1. Сбор данных

Один CSV на город на год в `app/data/raw/`. Полные годы при повторном запуске пропускаются,
поэтому команду можно перезапускать — если она оборвалась (лимит запросов, сеть), просто
запустите её снова. ~52 города × 40 запросов к архиву с паузой между ними: первый запуск
занимает несколько часов.

```bash
docker compose run --rm weather python -m app.collector --city all --years 40
docker compose run --rm weather python -m app.collector --city Riga            # один город
docker compose run --rm weather python -m app.collector --city Karaganda --lat 49.8 --lon 73.1
```

Архив Open-Meteo начинается с 1940 года и отстаёт от реального времени на несколько дней —
перезапустите позже, чтобы добрать свежие дни. Опциональный SOCKS5-прокси для API-запросов
задаётся в `.env`:

```
# изнутри контейнера прокси на хосте доступен как host.docker.internal
# ALL_PROXY=socks5h://host.docker.internal:1080
```

## 2. Обучение модели для каждого города

Один сэмпл = один день: ~30 признаков, описывающих предыдущие 30 дней (скользящие средние,
тренд, сезонность), предсказывают все 5 величин (температура, влажность, давление, ветер,
осадки) на каждый из следующих 30 дней. Лестница моделей — Dummy (общее среднее), климатология
(сезонное среднее, эталон для skill), Ridge, Random Forest — сравнивается на последнем годе,
который модель не видела при обучении; старые сэмплы получают линейно меньший вес (0,2 для
самого старого — проверено бенчмарком весов ниже: быстро теплеющим континентальным городам
вроде Алматы и Ташкента взвешивание нужно, некоторым европейским чуть лучше без него; 0,2 —
компромисс для всего парка). Победитель сохраняется вместе с метриками валидации в
`app/data/<City>-<model>.pkl`, заменяя предыдущий бандл города — устаревшие модели не
задерживаются.

Windows (PowerShell):

```powershell
Get-ChildItem app\data\raw\*.csv |
  ForEach-Object { $_.BaseName -replace '-\d+$', '' } |
  Sort-Object -Unique |
  ForEach-Object { docker compose run --rm weather python -m app.train --city $_ --max-years 10 }
```

Linux / macOS (bash; работает и в Git Bash на Windows):

```bash
for city in $(ls app/data/raw | sed 's/-[0-9]*\.csv//' | sort -u); do
  docker compose run --rm weather python -m app.train --city "$city" --max-years 10
done
```

`--max-years 10` следует рекомендации бенчмарка (ниже). Весь парк моделей — 30–60 минут.

## 3. Бенчмарки

Эксперимент с глубиной истории для одного города (только stdout, ничего не сохраняется):

```bash
docker compose run --rm weather python -m app.train --city Moscow --compare-years 10 20 30 --models ridge
```

Бенчмарк глубины истории по всему парку моделей — одна модель на город на глубину, сохраняет
`app/data/depth_benchmark.json`, отображается на `/fleet.html`:

```bash
docker compose run --rm weather python -m app.experiments depth
```

Бенчмарк весов сэмплов по всему парку моделей — помогает ли взвешивание по свежести (старейший сэмпл 0,2 →
новейший 1,0) при окне в 10 лет? Обучает ridge для каждого города с весами 0,2 / 0,5 / 1,0
(1,0 = без взвешивания), сохраняет `app/data/weight_benchmark.json`, отображается на
`/fleet.html`:

```bash
docker compose run --rm weather python -m app.experiments weight
```

Сводка по обученным моделям + поиск аномалий — без переобучения, читает метрики из бандлов,
сохраняет `app/data/benchmark.csv` + `benchmark.json` (тоже на `/fleet.html`); флаги: победа
dummy, явно отрицательный skill (< −0,05 — ничья с климатологией на таком горизонте
нормальна), |bias| > 1 °C, пробелы в данных, выбросы по IQR, расхождение конфигурации
валидации:

```bash
docker compose run --rm weather python -m app.benchmark
```

## Результаты бенчмарка глубины (2026-08-09, ridge, 52 города)

Каждая глубина валидируется на одном и том же последнем годе. Bias — средняя знаковая ошибка
(прогноз − факт).

| Глубина | Средний MAE, °C | Медианный MAE, °C | Средний bias, °C | Средний overall | Лучшая в городах |
|---------|-----------------|-------------------|------------------|-----------------|------------------|
| 10 лет | 2,576 | 2,565 | −0,08 | 0,614 | 25 |
| 20 лет | 2,566 | 2,545 | −0,35 | 0,607 | 19 |
| 30 лет | 2,581 | 2,550 | −0,48 | 0,608 | 8 |
| 40 лет | 2,593 | 2,570 | −0,55 | 0,610 | 0 |

**Рекомендация: обучать весь парк с `--max-years 10`.** Точность перестаёт расти после 20 лет
(10 и 20 лет отличаются на 0,01 °C — шум), а холодный bias монотонно растёт с глубиной —
старые десятилетия учат модель вчерашнему климату. 10 лет — лучшая глубина в 25 из 52 городов,
40 лет — ни в одном, а четверть данных означает самое быстрое обучение. Известное исключение:
Прибалтика/Скандинавия и Кавказ выигрывают от глубины (Таллин 3,00 → 2,85), но 20 лет дают
большую часть этого выигрыша, а настройка глубины на город принесла бы ~0,05 °C ценой
пер-городской конфигурации.

## API прогноза

`GET /api/cities` — обученные модели на диске как `{city: [models]}` ·
`GET /api/forecast?city=&model=` — прогноз на 30 дней (5 величин на день) ·
`GET /api/models?city=` — метрики валидации из бандла города · `GET /api/benchmark`,
`GET /api/depth-benchmark`, `GET /api/weight-benchmark` — сохранённые офлайн-отчёты ·
`GET /api/languages` — доступные переводы.

Признаки строятся из последних 45 дней реальной погоды с Open-Meteo и кэшируются до смены
календарного дня — не больше одного запроса наверх на город в день. Единицы отображения
европейские: давление в мм рт. ст. (хранится и моделируется в гПа), °C, м/с, мм. Прогнозы
обрезаются до физически возможных значений (без отрицательных осадков, влажность 0–100%).

Веб-интерфейс показывает месячный прогноз таблицей плюс графики plotly по каждому параметру,
с выпадающими списками города и языка (43 языка, автоопределение по настройкам браузера, выбор
запоминается в localStorage). `/model.html` — лестница моделей с MAE/bias/skill и кривая ошибки
по горизонту; `/fleet.html` — офлайн-отчёты бенчмарков.

## Модель безопасности

Нет записи, нет чувствительных данных — prod-контейнер открыт в интернет по чистому HTTP без
авторизации, как статический `hello_world.html`. HTTPS, авторизация и rate limiting намеренно пропущены.
